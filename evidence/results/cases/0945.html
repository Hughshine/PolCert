tiling-innerpar-satvec

Tiling was legal, but the parallel annotation was unsafe

What This Case Checks

Replays an optimizer proposal or hint that PolCert cannot certify.

Expected outcome
The route must reject or replace the uncertifiable effect described here: Pluto moves dependence-satisfaction bits to a tile dimension without constructing the schedule that would satisfy those dependences.
Recorded outcome
The legal rectangular tiling is accepted; the unsafe parallel loop is removed or rejected in strict mode.
Verdict
PASS means the expected rejection or certified fallback occurred at the declared boundary.
Why this test matters
These cases demonstrate that optimizer output is evidence to check, not a trusted correctness claim.

Original C Program

#include <stdio.h>

#define N 16

static int a[N][N];

int main(void) {
  int i, j;

  for (i = 0; i < N; i++) {
    a[i][0] = 1;
    a[0][i] = 1;
  }

#pragma scop
  for (i = 1; i < N; i++)
    for (j = 1; j < N; j++)
      a[i][j] = a[i - 1][j] + a[i][j - 1] + 1;
#pragma endscop

  printf("%d\n", a[N - 1][N - 1]);
  return 0;
}

Why Rejection Is Correct

Classification
Confirmed official Pluto tiling/parallel miscompilation
Reason
The two-dimensional recurrence has cross-tile dependences, so the selected tile loop is not parallel.
Optimizer behavior
Pluto moves dependence-satisfaction bits to an outer tile dimension and clears inner bits without constructing the schedule that would satisfy those dependences.
Correctness consequence
OpenMP tile interleavings violate the recurrence and produce nondeterministic wrong results.
PolCert response
PolCert accepts the legal rectangular tiling but independently rejects or removes the unsafe parallel overlay.
