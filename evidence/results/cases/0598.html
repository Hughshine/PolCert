const_unroll

Constant-bound loop unrolling

What This Case Checks

Instantiates the typed instruction interface with a handwritten C-like loop and compares baseline and optimized execution.

Expected outcome
Baseline and generated executions must produce the same output and all 1 declared structural-effect checks must match.
Recorded outcome
Required optimization effects occurred and optimized execution agrees with baseline.
Verdict
PASS means the recorded behavior matched the expected result for this case.
Why this test matters
These examples show that the abstract validators compose with a stateful, typed instruction semantics.

Source Loop Program

for i in range(0, 4) {
  A[i] = (i + 1);
}

Accepted Optimized Loop Program

A[0] = 1;
A[1] = 2;
A[2] = 3;
A[3] = 4;

Dynamic Execution

The two displayed Loop programs were lowered with Rocq Z.div/Z.mod control semantics, compiled, and run from the same deterministic state. The harness feeds every finite modeled scalar and array element into SHA-256 in a fixed order.

Term meanings

  • outputs-match: baseline and generated executions produced the same checked values.
  • effects-matched:true: every declared structural optimization effect was observed.
  • required-effects: number of structural markers that must be present.
  • forbidden-effects: number of structural markers that must be absent.
  • parallel: whether the generated Loop contains a general parallel loop.
  • vector: whether the generated Loop contains the restricted innermost parallel form.
  • unrolled: whether the generated Loop contains the declared unrolling effect.
  • omp-threads-requested: thread count used by the execution check, not a proof claim.
  • PASS: the expected acceptance, effect, refinement, or execution result was observed.
