matmul-parallel-hint

The requested parallel dimension was not certifiable

What This Case Checks

Replays an optimizer proposal or hint that PolCert cannot certify.

Expected outcome
The route must reject or replace the uncertifiable effect described here: The hinted coordinate cannot be certified as a safe generated parallel loop for this matrix-multiplication schedule.
Recorded outcome
Strict mode rejects with no output; permissive mode chooses a different certified dimension.
Verdict
PASS means the verified part was retained and the uncertifiable optional effect was not emitted.
Why this test matters
These cases demonstrate that optimizer output is evidence to check, not a trusted correctness claim.

Input Loop Program

context(M, N, K);

for i in range(0, M) {
  for j in range(0, N) {
    for k in range(0, K) {
      C[i][j] = ((beta * C[i][j]) + ((alpha * A[i][k]) * B[k][j]));
    }
  }
}

Strict validation stops before code generation, so this case has no target or rejected candidate program to display.

Why the Requested Effect Is Not Applied

Classification
Non-certifiable optimizer hint; no Pluto miscompilation claimed
Reason
The hinted coordinate cannot obtain the concrete certificate required for a generated parallel loop.
Optimizer behavior
No optimizer defect is established. Pluto supplies a hint, but a hint is not a proof of independence.
Correctness consequence
PolCert makes no claim that the raw Pluto program is wrong; it only refuses to emit an unproved annotation.
PolCert response
Strict mode emits no output. Permissive mode rejects the hint and selects a different dimension that passes validation.
