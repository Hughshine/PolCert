vanished-outer-parallel

A parallel annotation moved to a dependent inner loop

What This Case Checks

Replays an optimizer proposal or hint that PolCert cannot certify.

Expected outcome
The route must reject or replace the uncertifiable effect described here: After a one-trip outer coordinate disappears, an off-by-one band test transfers its parallel annotation to a dependent inner recurrence.
Recorded outcome
Strict hint mapping rejects the vanished loop, and a direct check also rejects the dependent inner loop.
Verdict
PASS means the expected rejection or certified fallback occurred at the declared boundary.
Why this test matters
These cases demonstrate that optimizer output is evidence to check, not a trusted correctness claim.

Original C Program

#include <stdio.h>

#define N 10000

static int a[1][N];

int main(void) {
  int i, j;
  a[0][0] = 1;

#pragma scop
  for (i = 0; i < 1; i++)
    for (j = 1; j < N; j++)
      a[i][j] = a[i][j - 1] + 1;
#pragma endscop

  printf("%d\n", a[0][N - 1]);
  return 0;
}

Why Rejection Is Correct

Classification
Confirmed official Pluto parallel-annotation miscompilation
Reason
The surviving inner loop carries a j-1 to j recurrence and therefore cannot use interleaving parallel semantics.
Optimizer behavior
After a one-trip outer coordinate disappears, an off-by-one band-boundary test transfers its parallel annotation to the dependent inner loop.
Correctness consequence
Parallel interleavings violate the recurrence; a recorded four-thread run changes the result from 10000 to 2499.
PolCert response
Strict hint mapping finds no surviving certifiable coordinate, and direct validation also rejects the dependent inner loop.
