unrolljam_dependent_guard

Block unrolling; unsafe loop jamming rejected

What This Case Checks

Instantiates the typed instruction interface with a handwritten C-like loop and compares baseline and optimized execution.

Expected outcome
Baseline and generated executions must agree; checked block unrolling must remain, while the dependence-crossing jam must be absent.
Recorded outcome
Baseline and optimized outputs matched. Checked block-unroll structure was present, and the forbidden dependence-crossing jam was absent.
Why this test matters
These examples show that the abstract validators compose with a stateful, typed instruction semantics.

Source Loop Program

context(N, M);

for i in range(1, N) {
  for j in range(0, M) {
    A[i][j] = (A[(i + -1)][(j + 1)] + 1);
  }
}

Why the Requested Effect Is Not Applied

Classification
Verified local fallback after an unsafe jam
Reason
The neighboring loop bodies carry a dependence, so jamming them would reorder a read and write. PolCert keeps checked block unrolling but leaves the dependent bodies as separate loops.

  • parallel: whether the generated Loop contains a general parallel loop.

  • unrolled: whether the generated Loop contains the declared unrolling effect.
