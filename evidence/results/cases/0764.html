parallel-multipar-three-dims

Parallelization of multiple loop dimensions

What This Case Checks

Exercises one Pluto-compatible driver option combination and its declared route or effect contract.

Expected outcome
The driver must accept the request and satisfy 4 effect contracts.
Recorded outcome
Route and optimization contract matched.
Verdict
PASS means the recorded behavior matched the expected result for this case.
Why this test matters
The wrapper must reject contradictory or unsupported requests and route accepted requests without silently dropping required effects.

Before Program

for i in range(0, 4) {
  for j in range(0, 4) {
    for k in range(0, 4) {
      A[((16 * i) + ((4 * j) + k))] = (A[((16 * i) + ((4 * j) + k))] + 1);
    }
  }
}

Accepted Program

parallel for i0 in range(0, 4) {
  parallel for i1 in range(0, 4) {
    parallel for i2 in range(0, 4) {
      A[((16 * i0) + ((4 * i1) + i2))] = (A[((16 * i0) + ((4 * i1) + i2))] + 1);
    }
  }
}

Dynamic Execution

The two displayed Loop programs were lowered with Rocq Z.div/Z.mod control semantics, compiled, and run from the same deterministic state. The harness feeds every finite modeled scalar and array element into SHA-256 in a fixed order.
