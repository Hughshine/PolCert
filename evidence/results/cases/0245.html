Candidate rejected; no unchecked program emitted

What This Case Checks

Checks the direct permutable-band tiling route and its output, alarm, and fallback behavior.

Expected outcome
The direct tiling route must reject the proposal, emit no optimized output and report the explicit rejection.
Recorded outcome
Direct-only route contract matched.
Why this test matters
The route boundary prevents malformed or inapplicable tiling proposals from reaching code generation.

Why Rejection Is Correct

Classification
No accepted direct tiling certificate
Reason
The request explicitly selects tiling, but this input has no loop band that can satisfy the tiling certificate.

Term meanings

  • optimized-output:false: the route emitted no optimized Loop program.
  • alarm:true: the driver reported the expected certification failure.
  • fallbacks:0: the route did not use an unchecked fallback.
  • PASS: the expected rejection, failure, or verified fallback was observed.
