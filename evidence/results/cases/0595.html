matmul

Parallelization

What This Case Checks

Checks both output agreement and the presence of the requested parallel-loop effect.

Expected outcome
Baseline and generated executions must produce the same output.
Recorded outcome
The source and optimized programs produced the same result. The optimized program shows parallelization. A parallel loop was present.
Why this test matters
A parallel test must establish both semantic agreement and that concurrency was actually emitted.

Before Program

context(M, N, K);

for i in range(0, M) {
  for j in range(0, N) {
    for k in range(0, K) {
      C[i][j] = ((beta * C[i][j]) + ((alpha * A[i][k]) * B[k][j]));
    }
  }
}

Accepted Program

context(M, N, K);

if ((1 <= M && (1 <= N && 1 <= K))) {
  parallel for i0 in range(0, ((M + 31) / 32)) {
    for i1 in range(0, ((N + 31) / 32)) {
      for i2 in range(0, ((K + 31) / 32)) {
        for i3 in range(max((32 * i0), 0), min(((32 * i0) + 32), M)) {
          for i4 in range(max((32 * i1), 0), min(((32 * i1) + 32), N)) {
            for i5 in range(max((32 * i2), 0), min(((32 * i2) + 32), K)) {
              C[i3][i4] = ((beta * C[i3][i4]) + ((alpha * A[i3][i5]) * B[i5][i4]));
            }
          }
        }
      }
    }
  }
}

Term meanings

  • outputs-match: baseline and generated executions produced the same checked values.
  • effects-matched:true: every declared structural optimization effect was observed.
  • parallel: whether the generated Loop contains a general parallel loop.
  • vector: whether the generated Loop contains the restricted innermost parallel form.
  • omp-threads-requested: thread count used by the execution check, not a proof claim.
  • PASS: the expected acceptance, effect, refinement, or execution result was observed.
