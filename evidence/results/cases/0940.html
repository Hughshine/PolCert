affine-fst-reversed

External grouping placed a consumer before its producer

What This Case Checks

Replays an optimizer proposal or hint that PolCert cannot certify.

Expected outcome
The route must reject or replace the uncertifiable effect described here: The supplied .fst grouping places a consumer before its producer, but Pluto accepts the complete lexicographically illegal schedule.
Recorded outcome
The affine checker rejects the schedule and the complete route emits no optimized loop.
Verdict
PASS means the expected rejection or certified fallback occurred at the declared boundary.
Why this test matters
These cases demonstrate that optimizer output is evidence to check, not a trusted correctness claim.

Original C Program

#include <stdio.h>

#define N 100

static int a[N];
static int b[N];

int main(void) {
  int i;

#pragma scop
  for (i = 0; i < N; i++) {
    a[i] = i + 1;
    b[i] = a[i];
  }
#pragma endscop

  printf("%d\n", b[N - 1]);
  return 0;
}

Why Rejection Is Correct

Classification
Unsafe optional Pluto control interface
Reason
The supplied .fst groups place a consumer before its producer, which is not a legal lexicographic schedule.
Optimizer behavior
Pluto installs the external grouping and later treats a positive loop coordinate as satisfying the dependence without rechecking the earlier negative scalar coordinate.
Correctness consequence
The consumer reads before the producer writes; the recorded result changes from 100 to 0.
PolCert response
The affine validator rejects the schedule and the complete route emits no optimized Loop.
